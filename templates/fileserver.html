File servers

What this is for: handsets, IP-DECT bases and gateways pull firmware and configuration files from a server on site. This serves one folder over whichever of HTTP, HTTPS, FTP and TFTP you switch on, so you don't have to stand up a separate server to commission or upgrade kit. Everything is off by default, and letting devices write files back is a separate switch per protocol.

Servers

Turn on only what the devices on this site actually need. Ports below 1024 (FTP 21, TFTP 69) need the service to run as Administrator on Windows or root on Linux — if a server won't start, the reason is shown against it.

HTTP

Plain HTTP. Simplest thing for a device to fetch a firmware file from, and what most newer kit expects.

Not 8080 — the GUI you're looking at owns that.
Permits PUT and POST writes into the folder.
Blank = no login required. Shared with HTTPS.

HTTPS

The same content over TLS, on its own port, using the HTTP username and password above.

Blank generates a self-signed certificate once and reuses it. Devices on a commissioning LAN won't be validating it.

No certificate is configured and this build can't generate one (the cryptography package is missing) — point the two boxes above at an existing certificate and key, or HTTPS won't start.

FTP

For older handsets and gateways that only speak FTP. Passive mode is supported, which is what most clients use by default.

Also permits rename, delete and folder creation.
Many devices log in as anonymous.
Open this range on the firewall as well as the control port, or passive transfers will hang.

TFTP

What most Ascom IP-DECT and older telephony kit uses for firmware and config. TFTP has no authentication of any kind — anyone who can reach the port can read the folder, and if uploads are on, write to it. Only run it on a network you control.

69 is the standard. Needs root/Administrator.
Unauthenticated writes — leave off unless a device genuinely needs to send its config back.
