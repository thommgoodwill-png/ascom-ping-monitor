Telligence monitoring settings

Point the monitor at this server's Telligence IMT bridge — its database and log. Defaults to the standard Ascom install location. On a customer site these are set on that site's agent instead.

Bridge source

Calls are display-only on the board by default; tick the last box only if you also want Emergency / bathroom calls to raise a webhook alert. The database gives the room/device inventory and names; the log carries the live call and fault transitions.
Flags the bridge as down if it stops writing its log/DB for that long — catches a crashed or hung bridge even while the server still pings. Naming the Windows service switches to an exact sc query check.

Telligence database — device type & serial

The bridge only knows a faulty device's address. Its type and serial live in the Telligence SQL Server database (DukaneESMMessages). Connect to it here so the fault drill-down can show the real device details.

Browse tables (read-only)

Call feed — ASCII stream over IP

Streams one line per live call to a third-party receiver (display board, paging gateway, logger). Each line is dutyarea|position|location|callstate using the human-friendly names, ending in a carriage return. Purely outbound — a Reset line only reflects that the nurse-call system cleared the call.

Example line: Test Rig|Bed|Bedroom 1|Patient Call
Sent on that interval with the same line ending. For the TCP client it also surfaces a dropped link so it reconnects.
